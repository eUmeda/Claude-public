# 引用地層図 — 見落とし検出ビューア v0.3.1

人間が（AI との対話で）組み上げた引用ツリー（既知リスト）を起点に、OpenAlex の
引用・被引用の海をクロールして、**関連研究の見落とし候補**を引用トポロジと語彙の
類似度で浮かび上がらせる補助道具。図は「上=新しい・下=古い」の年代軸に、横を
既知リストのクラスタで並べた全画面キャンバス。

- ビューア本体: `index.html`（自己完結・データ埋め込み済み・外部ライブラリ不要。約 14.9 MB）
- GitHub Pages: `https://<user>.github.io/Claude-public/citation-genealogy/`
- 公開済み Artifact: https://claude.ai/artifact/44wTSdKhvzR7bEBL8VvEFz
- 旧版 v0.2（8 起点・2 ホップ全網羅の地層図）: `v0.2/index.html`

## 使い方

1. 既知リストを `data/known_list.csv` に置く（列: `doi,cluster,phase,note`。cluster は任意の
   分類ラベル、phase はリストに加えた順序、note は表示名）。
2. `python3 fetch_crawl.py` で OpenAlex をクロール（キーは `openalex_key.md`。数分）。
3. `python3 build_finder.py` で `index.html` / `artifact.html` / `data/candidates.csv` を生成。
   候補の判定と検証は `finder_pipeline.py`、信号の計算は `finder_signals.py`。

## 候補の定義（v0.3.1）

既知文献 k と候補 w の各ペアに、3 つのチャネルから「つながりの強さ」s を付ける。

| チャネル | 量 | 強さ |
|---|---|---|
| 直接（D） | w が k を引用、または k が w を引用 | 1 |
| 共引用（CC） | k の引用者のうち w も引用する割合 frac（件数 cc ≥ 3、frac ≥ 1%） | 1 − exp(−frac / 0.03) |
| 書誌結合（BC） | 参照リストの重なりのコサイン bcos（共有 ≥ 3 本） | 1 − exp(−bcos / 0.10) |

s = 1 − (1−s_D)(1−s_CC)(1−s_BC)。ペアが「確か」なのは D があるか、cc ≥ 3 かつ frac ≥ 1.5%、
または共有 ≥ 3 本かつ bcos ≥ 0.04 のとき。候補ごとに **N = 確かなペアの数**、**S = s の合計**。

| tier | 名称 | 条件 |
|---|---|---|
| 1 | 要確認 | 既知リストの **2 件以上**と直接の引用関係 |
| 2 | 関連の可能性 | N ≥ 2（直接 1 件＋確かな共引用／書誌結合、または確かな間接関係 2 件以上） |
| 3 | 意味ベースの保険 | 引用ではつながらないが、TF-IDF コサインが背景分布の 97 パーセンタイル（0.22。要旨なしは 0.30）を超え、
最も近い既知文献と語幹を 3 語以上共有する。既知 1 件あたり 40 件・クラスタあたり 60 件・全体 300 件で打ち切り |
| 5 | 既知の別版 | 既知文献と DOI または正規化タイトル＋年が一致（プレプリント・再録など）。参照は既知側へ統合済み |
| 0 | 海 | 上のどれにも当たらない文献。位置だけ描き、詳細は埋め込まない |

汎用文献（R 本体、統計教科書など）は「既知に触れる辺の本数 ≥ 100 かつ取得集合内の被引用が期待の 2.5 倍以上」で
印を付け、ドロワーの既定では後ろに回す。総合スコア = S + 類似度の順位化（0〜1）。

### 同一文献の別レコード

OpenAlex には同じ論文が複数レコードで載ることがある（DOI 違い・タイトル同一）。DOI 一致、または
正規化タイトル（20 文字以上）＋年が一致するレコードを統合し、参照リストは和集合にする。今回は 690 件を統合。

### 検証（ホールドアウト）

既知リストの phase ≤ 2 の 8 件だけを既知として同じパイプラインを走らせ、残り 32 件がどの tier・順位で
浮上するかを見る（ビューアの「凡例・検証」に表も載せている）。

| 結果 | 件数 |
|---|---|
| 要確認 / 関連の可能性 / 意味ベース / 海 | 2 / 13 / 2 / 15 |
| 総合スコア順位 100 / 500 / 1000 位以内 | 5 / 9 / 9 |

海に落ちた 15 件の大半は 2015 年以降の新しい文献で、8 件との引用のつながりが 0〜3 本しかない。
クロールが「既知 2 件以上と共引用された文献」しか本体を取らないため、既知 1 件だけとつながる文献は
どの tier にも入れない（クロールの上限であり、判定の失敗ではない）。

## ビューアの見方

- **全画面キャンバス**。上部バー、左のドロワー（候補リスト）、右の詳細カード、凡例は図に重なる。
- **色＝クラスタ**（既知リストの分類）。横位置もクラスタの列。既知は太い輪郭＋ラベル常時表示。
  ●要確認、小さい●関連の可能性、◆意味ベースの保険、◎既知の別版、極小の点＝海。濃さ＝世界全体の被引用数（対数）。
- **ズーム**: 拡大すると縦（年）方向が先に伸びる。俯瞰では年×クラスタの密度帯、中間では候補と既知に触れる辺、
  接近では全文献にラベル。最大ズームで 1 年が画面の高さいっぱい、1 クラスタ列が画面の幅いっぱい。
  ホイール／ピンチ／＋−ボタンのほか、キー 1〜4 で段階ジャンプ（1 俯瞰・2 中間・3 接近・4 年間）、f で全体。
- **ドロワー**: tier・クラスタで絞り込み、スコア／S／N／直接接続数／類似度／被引用数／年で並べ替え。
  行をクリックで図が寄り、カードが開く。j/k で次・前の候補へ。
  「済（d）／追加（a）／除外（x）」の印はブラウザの localStorage に保存され、
  「追加候補を書き出し」で `known_list.csv` に追記できる CSV を表示する。
- **カード**: 書誌情報、DOI／OpenAlex リンク、「なぜ浮上したか」（既知文献ごとに 直接／共引用の件数と割合／
  共有参照数と強さ）、類似度と最も近い既知文献・共通語幹、汎用文献の注記、別版の注記、探索状態。
- **キーワード欄**: タイトル部分一致（重み 3）＋要旨索引の前方一致（重み 1）で関連文献だけを
  浮かび上がらせ、ドロワーも同じ集合に絞る。「年へ」に西暦を入れるとその年へ移動。Esc で閉じる。
- 動作中（ドラッグ・ピンチ・アニメーション）は薄い辺と海の点を間引き、止まると完全描画に戻る。

## データの範囲と限界

- 辺は OpenAlex が解決した参照関係のみ。辺が無いことは「引用なし」を意味しない。
- 候補の階層は機械的な分類で、内容上の関連を保証しない。最終判断は人間が行う。
- 既知 1 件だけとつながる文献はクロールの対象外（上のホールドアウト参照）。広げるにはクロール側の拡張が要る。
- 共引用の本体取得は上位 6,000 件で打ち切り（`status.json` に記録）。
- TF-IDF 類似度は語彙の重なりで、要旨が無い文献は低く出る。
- 生データ `data/crawl/*.json`（約 140 MB）と `data/finder.json` は Git 管理外。スクリプトとキーで再現する。

### OpenAlex の料金体系と取得時の制約

- 単一レコード取得（`/works/W...`）は無料（予算消費ゼロ）。
- 一覧クエリ（`/works?filter=...`）は 1 リクエスト 1 クレジット。**キー無しだと
  送信元 IP ごとの無料日次予算**から引かれるため、共有 IP のクラウド環境では
  すぐ枯渇する（今回は起点 8 件を取った時点で残高ゼロだった）。
- そこで後方 2 ホップは単一レコード取得を 8 並列で回して取り切った
  （`fetch_status.json` の `backward_mode: single`）。
- 前方（被引用）は `cites:` フィルタ＝一覧クエリが必須なので初回は打ち切り。
  その後ユーザーから API キーを受け取り `python3 fetch_openalex.py --citers-only`
  で 8 起点すべての被引用を取得した（一覧クエリ約 50 回）。

### 系譜の判定と主な結果（引用関係の事実として確認できたこと）

- 系譜 A/B の分類は「各起点から引用を **2ホップ以内**でたどって到達できるか」
  （他の起点で経路は止める）による機械的分類。無制限にたどると 2ホップ層どうしの
  引用でつながり 8,058 件中 4,984 件が「両系譜」になって意味を失うため、
  取得範囲と同じ深さで区切った。
- **両系譜の起点が直接引用する祖先（直接ブリッジ）: 1件のまま** — Bradshaw & Spies 1992
  (10.2307/2261007)。Keitt 2000 と Nicotra 1999 が引用。
- **2ホップ以内で両系譜から到達できる祖先: 264件**（v0.1 では見えなかった層）。
  到達する起点数が多い順に: Watt 1947 “Pattern and Process in the Plant Community”
  (5起点)、Pickett & White 1985 “The Ecology of Natural Disturbance and Patch
  Dynamics” (5起点・Gardner が直接引用)、White 1979 “Pattern, process, and natural
  disturbance in vegetation” (5起点)、Harper 1977 “Population Biology of Plants”
  (4起点・図内被引用 152)、Ripley 1981 “Spatial Statistics” (4起点・図内 128)、
  Cressie 1991 “Statistics for Spatial Data” (3起点・図内 268・Keitt/Lindgren が直接引用)。
- 2起点以上が直接引用する共通祖先: 13件（v0.1 と同数）。2ホップ以内で2起点以上から
  到達する文献: 647件。
- 後続文献のうち、**両系譜の起点を直接引用するものは 7 件**（例: Urban 2005
  “Modeling ecological processes across scales” が Gardner 1987 と Pacala 1996 を引用）、
  2 起点を引用するものは 460 件、1 起点のみが 7,397 件。
- これらは引用関係の事実であり、「内容上の系譜が同じ」という解釈とは別。

既知の限界:

- 辺は OpenAlex が解決した参照関係のみ。古い文献ほど参照リストが過少（Whittle 1954 は 9件、
  Monsi & Saeki は 10件）。辺が無いことは「引用なし」を意味しない。
- 2ホップ層と後続層は参照リストの ID だけ既知で、その先の文献は取得していない
  （図内にある文献への辺だけ描く）。詳細パネルの「探索状態」で区別している。
- 世界全体の被引用数（`cited_by_count`）はノードの濃さに使うが、質や関連性の指標ではない。

## ビューアの見方（v0.2）

- **縦軸＝年**（上が新しい）。10年ごとの地層帯。横軸は系譜の目安（左＝A 確率場・
  中立景観、右＝B 森林・光環境、中央＝両方から到達）で、正確な意味は持たない。
- **色**: 青＝A の祖先、アクア緑＝B の祖先、橙のひし形＝両系譜から到達（ブリッジ）、
  輪郭のみ＝後続（起点を引用する側）。
- **濃さ＝世界全体の被引用数**（対数）。**大きさ＝この図の中で引用されている数**（幹の太さ）。
  多くの経路が通る高被引用の祖先は濃く大きく、枝先は薄く小さい。辺も幹へ向かうものほど濃い。
- **クリック**で詳細パネル（DOI/OpenAlex リンク、要旨、探索状態、図内の引用・被引用リスト）と、
  祖先・子孫のハイライト。既定は 2 ホップまで（「ハイライト深さ」で 1/2/3/無制限）。
- **キーワード欄**: 未入力時はすべて等価値。入力するとタイトル・要旨・掲載誌との一致度で
  関連文献だけが浮かび（他は薄く）、右パネルに関連度順のリストが出る。要旨は全層で
  索引化済み（OpenAlex に要旨が無い文献はタイトルのみ）。
- **絞り込み**: 2ホップ層・後続層の表示切替、共通祖先のみ（2起点以上から到達）、
  枝の刈り込み（図内で引用されている数の下限。後続文献は引用している起点の数でも可）。
  **初期状態は「3 以上」**で、15,862 件のうち約 7,900 件（幹寄りの半分）だけを描いて
  地層の構造を見せる。「なし」で全文献。
- **要旨の索引**: 2ホップ層・後続層の要旨は本文を埋め込まず、語（英語・語幹化）ごとに
  該当ノードの一覧を圧縮した索引だけを持つ（`kw` フィールド、約 2 MB）。キーワード欄は
  タイトルの部分一致（重み 3）と索引の前方一致（重み 1）を合算する。

## OpenAlex API キーの引き継ぎ

被引用数・著者・abstract・前方探索の拡張（v0.2）は OpenAlex API を使う。

- キーは `citation-genealogy/openalex_key.md` に置く（**Git 管理外**。
  ルートの `.gitignore` で除外済み。コミット禁止）。
- 書式は次の2行を含めばよい: `api_key: <キー>` / `mailto: <メールアドレス>`
- セッションのコンテナは使い捨てなので、新しいセッションでは
  キーファイルを再アップロードして同じ場所に置き直す。
- 取得は `python3 fetch_openalex.py --test`（接続確認）→
  `python3 fetch_openalex.py`（全件取得、`data/openalex/` に保存）。
- **注意**: キーだけでは足りない。実行環境のネットワーク許可に
  `api.openalex.org` が追加されている必要がある（claude.ai/code の
  環境設定 → ネットワークアクセス）。

## v0.2 の仕様（2026-09-22 ユーザーと決定済み・実装済み）

1. **データ経路**: OpenAlex（`fetch_openalex.py`）。キーは任意だが、前方（被引用）の
   全件取得にはキーが実質必須（上記の料金体系）。
2. **前方（被引用）の見せ方**: 被引用数の多さは**ノードの濃さ**。
   「複数の起点・系譜を引用する文献」はキーワード未入力時は特別扱いせず等価値。
   キーワード入力時は関連する論文を優先表示（関連度で強調・絞り込み）。
3. **後方の探索深さ**: **2ホップ全網羅**（実施済み・打ち切りなし）。
4. **表示面**: Canvas 描画（辺・ノード）＋ quadtree ヒットテストに移行。幹を濃く、枝を薄く。
